# 1.5 Segment Groups

| Field | Detail |
|---|---|
| ID | 1.5 |
| Layer | Data Management |
| Status | Done |
| Depends On | 1.2.1, 1.2.3 |
| Milestone | M1 |

## Purpose

Allow named logical sub-units to be defined within a segment configuration. For composite lights (like DEE — Dee-LightOmation), this lets the system distinguish between physically and semantically distinct groups such as "Hearts" (segments 0–2) and "Letters" (segments 3–5). These groups let the transposition engine route a master preset to only the relevant sub-unit on the target light.

Segment groups also provide the per-segment characteristic colour: the `[R,G,B]` identity colour that defines how each physical unit looks when it is "itself" (e.g. Heart 1 is always red, Heart 2 is always purple). This characteristic colour is used by the `segment` colour mode during generation.

## Background

From the DEE preset data analysis:

- 200 LEDs, 6 segments: `0–67` (Heart 1), `67–118` (Heart 2), `118–155` (Heart 3), `155–172` (D), `172–186` (E), `186–200` (E)
- Per-segment characteristic colours detected from all presets: `seg[0]=[255,40,40]`, `seg[1]=[180,0,255]`, `seg[2]=[255,74,252]`, `seg[3–5]=[255,74,252]`
- These colours are consistent across all presets — the effect and palette change but `col[0]` per segment stays the same
- Some presets target only Hearts (e.g. "Solid-Hearts"), some only Letters (e.g. "Solid-Dee"), some both

## Responsibilities

- Add `LightSegmentGroup` and `LightSegmentGroupMember` models
- Add `colour` column to `LightSegmentConfigEntry` for characteristic colour storage
- Provide CRUD API for groups within a segment config
- Allow segment entries to be assigned to and removed from groups
- Detect characteristic colours automatically from imported preset data (most common `col[0]` per segment index across all presets)
- Display groups and characteristic colours in the segment config UI
- Allow master preset `segment_group_hint` (set in Module 1.3) to be used for group-targeted transposition

## Data Model

### New tables

```
LightSegmentGroup
  id            INTEGER PK
  config_id     INTEGER FK → light_segment_configs.id  (cascade delete)
  name          TEXT NOT NULL        -- e.g. "Hearts", "Letters", "Left arm"
  description   TEXT                 -- nullable
  display_order INTEGER DEFAULT 0

LightSegmentGroupMember
  id            INTEGER PK
  group_id      INTEGER FK → light_segment_groups.id  (cascade delete)
  entry_id      INTEGER FK → light_segment_config_entries.id  (cascade delete)
```

### Existing table update

`LightSegmentConfigEntry` — `colour` column (nullable TEXT, stored as JSON `"[R,G,B]"`). Added via migration in Module 1.2.3 but populated here.

## Characteristic Colour Detection

When scanning a `presets.json` import, for each segment index across all scanned presets, record the `col[0]` value. The most common value (mode) for each segment index is stored as the characteristic colour for that entry in the resulting segment config. This is called automatically after a successful scan.

The user can override the detected colour manually using a colour picker in the segment config UI.

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/lights/{light_id}/segment-configs/{config_id}/groups` | List all groups for a config |
| POST | `/api/v1/lights/{light_id}/segment-configs/{config_id}/groups` | Create a group |
| GET | `/api/v1/lights/{light_id}/segment-configs/{config_id}/groups/{group_id}` | Get a group with its member entries |
| PUT | `/api/v1/lights/{light_id}/segment-configs/{config_id}/groups/{group_id}` | Update group name/description/order |
| DELETE | `/api/v1/lights/{light_id}/segment-configs/{config_id}/groups/{group_id}` | Delete a group (members unaffected) |
| PUT | `/api/v1/lights/{light_id}/segment-configs/{config_id}/groups/{group_id}/members` | Replace member list (list of entry IDs) |
| POST | `/api/v1/imports/{import_id}/detect-colours` | Detect and store characteristic colours from a presets.json import |

## UI

- **Segment config detail** — shows each entry with its LED range, Y range (if matrix), and a colour swatch if a characteristic colour is set
- **Group editor** — within a config, lists all groups; each group shows its member entries; entries can be dragged between groups; "No group" bucket for unassigned entries
- **Colour picker** — per-entry inline colour picker to set or override the characteristic colour; auto-detected colour shown as default

## Key Rules and Constraints

- A segment entry can belong to multiple groups (e.g. "All hearts" and "Top heart")
- A group must contain at least one entry
- Group names must be unique within a config
- Groups are optional — most lights will not need them
- Deleting a group does not delete the entries; only the membership links are removed
- Characteristic colour detection is advisory — it suggests colours from the data but the user always has final control
- A master preset with no `segment_group_hint` targets all segments (default behaviour, no change from 1.2.1)

## DEE Example

DEE's "All segments" config would have:

```
Groups:
  Hearts  → entries: [Heart 1 (0–67, [255,40,40]), Heart 2 (67–118, [180,0,255]), Heart 3 (118–155, [255,74,252])]
  Letters → entries: [D (155–172, [255,74,252]), E1 (172–186, [255,74,252]), E2 (186–200, [255,74,252])]
```

A master preset with `segment_group_hint="Hearts"` would only activate the first three segments; the Letters segments would be set to `stop=0`.
