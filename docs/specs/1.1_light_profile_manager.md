# 1.1 Light Profile Manager

| Field | Detail |
|---|---|
| ID | 1.1 |
| Layer | Data Management |
| Status | Backlog |
| Depends On | 0.4 |
| Milestone | M1 |

## Purpose

Allow users to create and manage light profiles. Each profile captures everything the system needs to know about a physical LED light: its total LED count, segment layout, connection details, and metadata.

## Responsibilities

- Create, read, update, and delete light profiles
- Manage segment definitions for each light (add, edit, remove, reorder segments)
- Validate that segment definitions cover the full LED range without gaps or overlaps
- Display a summary of each light's profile including segment visualisation

## Out of Scope

- Importing segment data from a `cfg.json` file (Module 1.2)
- Managing multiple named segment configurations per light (Module 1.2.1)
- Connecting to or communicating with the physical device (Module 3.2)
- Assigning presets to a light (Module 1.4)

## Inputs

- User-entered light name, IP address, mDNS hostname, total LED count, firmware version, location, notes
- User-entered segment definitions: index, name, start LED, stop LED

## Outputs

- Persisted light record in `lights` table
- Persisted segment records in `light_segments` table
- Change log entries for create/update/delete operations

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/lights` | List all lights |
| POST | `/api/v1/lights` | Create a light |
| GET | `/api/v1/lights/{id}` | Get a light with its segments |
| PUT | `/api/v1/lights/{id}` | Update a light's metadata |
| DELETE | `/api/v1/lights/{id}` | Delete a light |
| GET | `/api/v1/lights/{id}/segments` | List segments for a light |
| PUT | `/api/v1/lights/{id}/segments` | Replace all segments for a light |

## UI Screens

- **Light list** — all lights with name, IP, total LEDs, segment count, and quick-action links
- **Light detail / edit form** — all fields editable; segment editor below
- **Segment editor** — add/edit/remove segments with start/stop inputs; live coverage indicator showing used vs total LEDs and any gaps

## Key Rules and Constraints

- A light name must be unique
- Segment `start_led` must be less than `stop_led`
- Deleting a light must warn if the light has existing assignments, generated files, or import history
- Segment indices must be contiguous starting from 0
- The coverage indicator must flag gaps and overlaps in real time without requiring a save

## Acceptance Criteria

- [ ] Can create a light with name, IP, and total LEDs
- [ ] Can add, edit, and remove segments; segment order is preserved
- [ ] Saving a segment set that has gaps or overlaps shows a warning (save is still permitted)
- [ ] Deleting a light that has associated data shows a confirmation with a count of affected records
- [ ] RB Proto and Small Rainbow profiles created by seed data display correctly
- [ ] Change log records all create, update, and delete events
