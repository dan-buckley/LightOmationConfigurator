# 1.2 File Import

| Field | Detail |
|---|---|
| ID | 1.2 |
| Layer | Data Management |
| Status | Backlog |
| Depends On | 0.4 |
| Milestone | M1 |

## Purpose

Allow users to bring WLED `presets.json` and `cfg.json` files into the system, either by uploading a file manually or fetching it from a reachable WLED device on the network. Every imported file is retained permanently.

## Responsibilities

- Accept `presets.json` and `cfg.json` via file upload
- Accept `presets.json` and `cfg.json` via network fetch from a WLED device IP (delegates the actual HTTP call to Module 3.2)
- Validate that the uploaded or fetched content is valid JSON
- Store the raw JSON in `imported_files` with metadata (light, file type, source, timestamp)
- After a successful `cfg.json` import, offer to extract LED count and segment data to pre-populate or update the associated light profile
- Display import history per light with timestamps and source
- Auto-discovery of unique segment configurations from a `presets.json` import is handled in Module 1.2.1

## Out of Scope

- Parsing preset data into the master preset library (Module 1.3)
- Triggering generation or deployment (Modules 2.2, 3.2)
- The actual HTTP request to the WLED device (Module 3.2 provides this)

## Inputs

- File upload: `multipart/form-data` with the JSON file and the target light ID
- Network fetch: light ID (the device IP is read from the light profile)

## Outputs

- New record in `imported_files` with `raw_json`, `light_id`, `file_type`, `source`, `imported_at`
- Optional: updated `lights` and `light_segments` records if the user accepts the `cfg.json` extraction
- Change log entry

## API Endpoints

| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/imports/upload` | Upload a file for a specific light |
| POST | `/api/v1/imports/network/{light_id}` | Trigger network fetch (proxies to Module 3.2) |
| GET | `/api/v1/imports` | List all imports (optionally filtered by light) |
| GET | `/api/v1/imports/{id}` | Get a specific import record with raw JSON |
| POST | `/api/v1/imports/{id}/extract-profile` | Extract and apply light profile data from a cfg import |

## UI Screens

- **Import screen** — select light, choose file type, upload or trigger network fetch
- **Import history** — list of all imports per light with type, source, and timestamp; link to view raw JSON
- **Extract profile prompt** — shown after a `cfg.json` import; previews the extracted LED count and segments; user confirms before applying

## Key Rules and Constraints

- Raw JSON is stored exactly as received; no transformation at import time
- An import record is never deleted or overwritten
- If the uploaded file is not valid JSON, the import is rejected with a clear error before anything is written to the database
- Network fetch requires the light to have a valid IP address set in its profile
- If a `cfg.json` extraction is accepted and the light already has segment data, the user must confirm overwrite

## Acceptance Criteria

- [ ] Can upload a `presets.json` for RB Proto; raw JSON stored and visible in import history
- [ ] Can upload a `cfg.json` for Small Rainbow; raw JSON stored and extraction prompt shown
- [ ] Accepting extraction updates the light profile with correct LED count and segments
- [ ] Invalid JSON file is rejected before writing to the database
- [ ] Import history shows all records for a light in reverse chronological order
- [ ] Network fetch endpoint delegates to Module 3.2 and stores the result as an import
