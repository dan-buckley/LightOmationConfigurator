# 3.1 Export Manager

| Field | Detail |
|---|---|
| ID | 3.1 |
| Layer | Output |
| Status | Backlog |
| Depends On | 2.3 |
| Milestone | M2 |

## Purpose

Allow users to download a generated and validated `presets.json` file for manual upload to a WLED device. Record every export event permanently.

## Responsibilities

- Serve a generated file as a downloadable JSON file
- Enforce that validation must pass before a download is permitted
- Record the export event in `exported_files` with the method, timestamp, and reference to the generated file
- Display export history per light

## Out of Scope

- Network push to a WLED device (Module 3.2)
- Generating the file (Module 2.2)
- Validating the file (Module 2.3)

## Inputs

| Input | Description |
|---|---|
| `generated_file_id` | ID of the record in `generated_files` to export |

## Outputs

| Output | Description |
|---|---|
| File download | The raw JSON content served as `presets.json` with `Content-Disposition: attachment` |
| `exported_files` record | Export event recorded with method `download`, timestamp, and `generated_file_id` |

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/exports/{generated_file_id}/download` | Download the generated file (runs validation first) |
| GET | `/api/v1/exports` | List export history (filterable by light) |
| GET | `/api/v1/exports/{id}` | Get a specific export record |

## UI Screens

- **Export action** — available on the generation result view and the light detail page; shows validation status; Download button enabled only if validation passes; one-click download
- **Export history** — list of all exports per light with timestamp, method, and link to the associated generated file

## Key Rules and Constraints

- A download must not proceed if the validation engine returns Fail for the associated generated file
- The validation check at download time is the definitive check; the user cannot bypass it without changing the generated file
- The exported file must be named `presets.json` in the download
- Export records are never deleted

## Acceptance Criteria

- [ ] A generated file that passes validation can be downloaded as `presets.json`
- [ ] A generated file that fails validation cannot be downloaded; the UI shows the validation failure reason
- [ ] Every successful download creates a record in `exported_files`
- [ ] Export history shows all downloads for a light in reverse chronological order
- [ ] The downloaded file content exactly matches the stored `raw_json` in `generated_files`

## Open Questions

- Should there be a way to export any historical generated file (not just the latest), with a clear indication it is not the current version?
