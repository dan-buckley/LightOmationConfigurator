## Purpose

Establish the React application shell, navigation structure, API client, and shared UI conventions so that all subsequent modules have a consistent frontend base to build on.

## Responsibilities

- Initialise the React application (Vite recommended for fast dev builds)
- Define the top-level navigation layout: sidebar or top nav with links to each main section
- Set up client-side routing with a route per module area
- Create a typed API client module (using `fetch` or `axios`) that points to the backend base URL from environment config
- Define shared UI components: loading spinner, error boundary, empty state, confirmation modal
- Display a connection status indicator showing whether the backend is reachable (polls `/health`)
- Provide a consistent page layout component used by all module views

## Out of Scope

- Implementation of any module-specific pages beyond the nav shell and placeholder routes (handled per module)
- Backend code

## Shared Components

| Component | Purpose |
|---|---|
| `PageLayout` | Consistent page wrapper with title and action area |
| `LoadingSpinner` | Standard loading state |
| `ErrorMessage` | Standard error display with message |
| `EmptyState` | Standard empty list/data state |
| `ConfirmModal` | Reusable confirmation dialog for destructive actions |
| `StatusBadge` | Colour-coded status label (matches build plan statuses) |

## Key Rules and Constraints

- Backend base URL must be read from an environment variable (`VITE_API_BASE_URL`)
- The API client must include consistent error handling: network errors, `4xx`, and `5xx` all surface a typed error object
- All API calls must show a loading state while in flight
- The connection status indicator must not block the UI if the backend is unreachable
- Hot-reload must work in development (Vite default)

## Acceptance Criteria

- [ ] App loads at `http://localhost:3000` with navigation visible
- [ ] Each route renders a placeholder page with the correct title
- [ ] Backend connection status shows green when backend is up, red when unreachable
- [ ] API client returns a typed error for `4xx`/`5xx` responses
- [ ] `ConfirmModal` blocks navigation and requires explicit confirmation before proceeding
- [ ] App builds to static files with `npm run build` without errors
