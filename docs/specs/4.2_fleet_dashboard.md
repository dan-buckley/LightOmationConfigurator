# 4.2 Fleet Dashboard

| Field | Detail |
|---|---|
| ID | 4.2 |
| Layer | Visibility |
| Status | Backlog |
| Depends On | 4.1 |
| Milestone | M4 |

## Purpose

Provide a single-screen overview of the entire fleet of lights, showing the status of each light at a glance and surfacing lights that need attention. The dashboard is the home screen of the application.

## Responsibilities

- Display all registered lights with their key status indicators
- Show last import date, last generation date, and last deployment date per light
- Flag lights where the last generated file is newer than the last deployment (out of sync)
- Flag lights with no generated file or no deployment on record
- Provide quick-action links from each light card to import, generate, and deploy workflows
- Show a summary count of total lights, lights in sync, and lights needing attention

## Out of Scope

- Performing any actions directly (dashboard links navigate to the relevant module screens)
- Showing the content of preset files

## Data Sources

| Table | What it contributes |
|---|---|
| `lights` | Light names and metadata |
| `imported_files` | Last import date per light |
| `generated_files` | Last generation date per light |
| `exported_files` | Last manual export date per light |
| `deployment_history` | Last network deployment date and result per light |

## Status Definitions

| Status | Meaning |
|---|---|
| In Sync | Last deployment matches last generated file |
| Needs Deploy | A generated file exists that is newer than the last deployment |
| Not Generated | Light has imports but no generated file |
| No Activity | Light profile exists but no imports or generated files |

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/dashboard` | Returns summary and per-light status for all lights |

## UI Screens

- **Dashboard** — summary bar at the top (total lights, in sync, needs attention); grid or table of light cards below; each card shows name, IP, LED count, last import/generate/deploy dates, status badge, and quick-action buttons

## Key Rules and Constraints

- The dashboard endpoint must be efficient; it should not issue per-light queries (use aggregated joins)
- Status is computed server-side and returned as part of the dashboard response
- The dashboard must load correctly even when some lights have no history at all

## Acceptance Criteria

- [ ] Dashboard loads and shows all registered lights
- [ ] Status badges reflect actual data (a newly generated file shows Needs Deploy until a deployment is recorded)
- [ ] Quick-action links navigate to the correct module with the light pre-selected
- [ ] Summary counts are correct
- [ ] Dashboard loads without error when a light has no imports or generated files

## Open Questions

- Should the dashboard show online/offline status for network-connected lights (requires a live ping per light on page load — may be slow)?
- Should there be a manual refresh button, or should the dashboard poll for updates automatically?
