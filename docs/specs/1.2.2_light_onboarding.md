# 1.2.2 Light Onboarding from CFG

| Field | Detail |
|---|---|
| ID | 1.2.2 |
| Layer | Data Management |
| Status | Backlog |
| Depends On | 1.2 |
| Milestone | M1 |

## Purpose

Allow a new light to be created directly from a `cfg.json` upload without requiring the user to manually create the light record first. The light name and total LED count are extracted automatically from the file, removing friction when onboarding lights that have not yet been registered in the system.

## Background

The current import upload endpoint (`POST /api/v1/imports/upload`) requires a `light_id` form parameter. This means the user must first create the light in Module 1.1, then return to the import page to upload its cfg. This is an unnecessary two-step process when the cfg file itself contains all the information needed to create the light.

Two lights currently blocked by this limitation:
- **Dee-LightOmation** (`wled_presets_Dee-LightOmation_blue_variants.json`) — 200 LEDs, 6 segments, composite type
- **WLED-Small_MATRIX** (`wled_presets_WLED-Small_MATRIX.json`) — 1536 LEDs, 48×32 matrix, matrix type

## Responsibilities

- Make `light_id` optional when `file_type=cfg`
- When `light_id` is omitted and `file_type=cfg`: extract `id.name` and `hw.led.total` from the uploaded file, create a new `Light` record if no matching name exists, link the import to the resulting light
- If a light with the same name already exists, link the import to that light without creating a duplicate
- Return a `light_created` boolean in the upload response
- Update the import form UI so "Select light" is optional when file type is `cfg`, with a helper note
- Provide seed data for DEE and Small_MATRIX using this flow

## No Schema Changes

The existing `lights` and `imported_files` tables require no schema changes. This is a behavioural extension to the upload endpoint only.

## API Change

`POST /api/v1/imports/upload`

| Parameter | Before | After |
|---|---|---|
| `light_id` (form) | Required | Optional when `file_type=cfg` |
| `light_created` (response) | Not present | `true` if a new light was created, `false` if linked to an existing one |

When `light_id` is omitted and `file_type=cfg`:
1. Parse the uploaded JSON
2. Extract `cfg["id"]["name"]` → light name
3. Extract `cfg["hw"]["led"]["total"]` → total LEDs
4. Look up a `Light` with that name
5. If not found: create a `Light` with the extracted values; all other fields (IP, location, notes, `light_type`, `shortcode`) default to null/blank
6. Link the import to the resulting light (new or existing)

When `light_id` is omitted and `file_type=presets`:
- Return `422 Unprocessable Entity` — presets files do not contain enough information to auto-create a light

## UI Change

Import upload form:
- When file type is `cfg`, the "Select light" dropdown becomes optional
- Placeholder text changes to: "Leave blank to create a new light from this file"
- On success, if `light_created=true`, show an inline notice: "New light '{name}' created from this file"

## Key Rules and Constraints

- Auto-created lights are created with only `name` and `total_leds` populated; the user fills in IP, location, and notes via the light profile editor
- `light_type` and `shortcode` on auto-created lights default to null/blank and are set by the user or auto-detected by Module 1.2.3 if the cfg contains a matrix block
- If `light_id` is provided, it is used as-is (existing behaviour unchanged)
- The `extract-profile` action (applying cfg to update a light's segments) remains unchanged — it still requires a `light_id`

## Acceptance Criteria

- [ ] Uploading a `cfg.json` without selecting a light creates a new light with the correct name and total LED count
- [ ] Uploading a `cfg.json` for an existing light name links to the existing light without creating a duplicate
- [ ] `light_created: true` is returned in the response when a new light is created
- [ ] Uploading a `presets.json` without selecting a light returns `422`
- [ ] Auto-created light appears in the light list and can have its IP, location, and notes filled in
- [ ] Seed data creates DEE (Dee-LightOmation, 200 LEDs) and Small_MATRIX (WLED-Small_MATRIX, 1536 LEDs) via this flow
