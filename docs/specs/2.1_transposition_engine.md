# 2.1 Transposition Engine

| Field | Detail |
|---|---|
| ID | 2.1 |
| Layer | Processing |
| Status | Backlog |
| Depends On | 1.1, 1.2.3, 1.5 |
| Milestone | M2 |

## Purpose

The core logic of the application. Given a master preset and a target light profile, produce a correctly transposed preset that retains all effect settings from the source while substituting the target light's LED layout.

## Responsibilities

- Transpose each supported preset type from a source layout to a target layout
- Handle all-LED presets: replace total LED range with target total
- Handle segmented presets: map each segment's `start` and `stop` to the corresponding target segment by index
- Handle matrix presets: map 2D `start`/`stop` + `startY`/`stopY` regions proportionally from source to target
- Handle composite presets with a `segment_group_hint`: map segments only within the named group on the target light
- Handle playlist presets: remap internal preset ID references to their target IDs (provided by the caller)
- Handle button presets: pass through unchanged
- Handle build presets: treat as segmented with sequential segment activation
- Apply colour substitution when `colour_mode=segment`: replace `col[0]` per segment with the characteristic colour from the target light's segment config
- Apply palette override when `palette_override` is set on the assignment
- Preserve all other effect settings: effect ID, palette, speed, intensity, mirroring, reverse, and all option flags
- Be fully testable without a database or HTTP connection (pure function)

## Out of Scope

- Reading from or writing to the database (the caller provides all required data)
- Generating a complete `presets.json` file (Module 2.2)
- Validating the transposed result (Module 2.3)

## Inputs

| Input | Type | Description |
|---|---|---|
| `master_preset` | dict | The raw WLED preset JSON object for a single preset |
| `source_profile` | LightProfile | Source light total LEDs and segment list (start/stop per index) |
| `target_profile` | LightProfile | Target light total LEDs, segment list, and segment config entries (with characteristic colours) |
| `target_preset_id` | int | The preset ID to assign in the output |
| `playlist_id_map` | dict (optional) | Maps source preset IDs to target preset IDs (for playlist resolution) |
| `colour_mode` | str (optional) | `"source"` \| `"segment"` \| `"custom"` (default `"source"`) |
| `palette_override` | int (optional) | Override palette ID for all segments |
| `colour_slots` | list (optional) | Per-segment `[R,G,B]` overrides when `colour_mode="custom"` |
| `segment_group_hint` | str (optional) | Name of the segment group to target on the target light (for composite lights) |

## Outputs

| Output | Type | Description |
|---|---|---|
| `transposed_preset` | dict | The transposed WLED preset JSON object with the target layout applied |

## Transposition Rules

### All-LED preset
- A preset with a single segment covering the full LED range of the source light
- Output: single segment with `start=0`, `stop=target_profile.total_leds`
- All effect settings preserved

### Segmented preset
- A preset with multiple segments aligned to the source light's segment boundaries
- Output: same number of segments; segment `i` gets `start` and `stop` from `target_profile.segments[i]`
- If target has fewer segments than the source preset, excess source segments are dropped and a warning is returned
- If target has more segments than the source preset, unmatched target segments are left with `stop=0` (WLED inactive convention)
- All per-segment effect settings preserved

### Playlist preset
- A preset whose structure is a WLED playlist (`ps` array of preset IDs, `dur`, `transition`)
- Output: playlist preset IDs are replaced using `playlist_id_map`; any source ID not in the map is flagged as unresolvable
- Duration and transition values preserved

### Button preset
- A preset using a WLED `win` command string
- Output: returned unchanged (layout-independent)

### Build preset
- Treated as segmented; segment activation order is preserved

### Matrix preset
- A preset on a `matrix` light where segments carry both X (`start`/`stop`) and Y (`startY`/`stopY`) coordinates
- Output: map the source 2D region proportionally to the target 2D region
  - X range: `new_start = round(src_start / src_width * tgt_width)`, similarly for stop
  - Y range: `new_start_y = round(src_start_y / src_height * tgt_height)`, similarly for stop_y
- If source and target have different aspect ratios, transpose as closely as possible and include a warning
- All per-segment effect settings (including `rY`, `mY`, `m12`, `tp`) preserved unchanged

### Composite / group preset
- A preset with a `segment_group_hint` targeting a named group on a composite light
- Locate the named group in `target_profile.segment_configs[active].groups`
- Map source segment index `i` to `group.entries[i]` (the i-th entry in that group)
- Segments on the target light that are **not** in the named group are set to `stop=0` (WLED inactive)
- If the named group does not exist on the target light, return an error (not a warning) — this is a configuration mistake
- If the source preset has more segments than the group has entries, excess source segments are dropped with a warning

### Colour substitution
- Applied after layout transposition, before returning the output
- Controlled by the `colour_mode` input:
  - `source`: no colour changes — colours from the master preset are preserved as-is
  - `segment`: replace `col[0]` on each output segment with `target_profile.segment_config.entries[i].colour` (if set); if the entry has no characteristic colour, preserve the source colour for that segment
  - `custom`: replace `col[0]` on segment `i` with `colour_slots[i]` (if provided); fall back to source colour for segments with no slot override
- `col[1]` and `col[2]` (secondary and tertiary effect colours) are never overridden by colour substitution
- If `palette_override` is set, replace `pal` on all output segments with the given palette ID

## Key Rules and Constraints

- The engine must not have side effects; it takes inputs and returns outputs only
- If the source preset type cannot be determined, the engine returns an error rather than guessing
- Transposition warnings (dropped segments, unresolved playlist IDs) are returned alongside the output, not as exceptions
- The engine must have a comprehensive unit test suite covering all preset types and edge cases

## Acceptance Criteria

- [ ] All-LED preset from RB Proto (388 LEDs) transposed to Small Rainbow (182 LEDs) produces `stop=182`
- [ ] Segmented preset from RB Proto transposed to Small Rainbow produces correct per-segment boundaries
- [ ] Matrix preset from Small_MATRIX transposed proportionally to a differently-sized matrix produces correct X and Y ranges
- [ ] Composite preset with `segment_group_hint="Hearts"` targets only the Hearts group entries on DEE; Letters segments are `stop=0`
- [ ] Composite preset referencing a group that does not exist on the target returns an error
- [ ] Playlist preset with ID remapping resolves all IDs correctly
- [ ] Button preset passes through unchanged
- [ ] Source preset with more segments than the target produces a warning and drops excess segments
- [ ] `colour_mode=segment` replaces `col[0]` on each segment with the characteristic colour from the target config entries
- [ ] `colour_mode=segment` falls back to source colour for segments with no characteristic colour set
- [ ] `palette_override` replaces `pal` on all output segments
- [ ] Unit tests pass for all preset types including edge cases
- [ ] Engine raises a typed error (not an unhandled exception) for malformed input

## Open Questions

- How should mismatched segment counts be handled in UI — show warning at assignment time or only at generation time?
- Should proportional mapping (scale segment sizes to fit target) be a future option for 1D segmented presets, or is index-based mapping sufficient? (Matrix already uses proportional mapping.)
