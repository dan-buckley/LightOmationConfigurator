# 1.4 Light Preset Assignments

| Field | Detail |
|---|---|
| ID | 1.4 |
| Layer | Data Management |
| Status | Done |
| Depends On | 1.1, 1.3 |
| Milestone | M1 |

## Purpose

Define which master presets should appear on a specific light, what preset ID they should be assigned, and what quick-access label they should use. Assignments are the instruction set that the generation engine uses to build a target `presets.json`.

## Responsibilities

- Create, read, update, and delete preset assignments for a light
- Enforce unique target preset IDs within a light
- Enforce unique quick-labels within a light
- Allow assignments to be reordered (sort order affects generation order)
- Validate that target preset IDs fall within the light's `preset_slot_scheme` ranges (warn on conflict)
- Show a summary of assigned presets including their source and target IDs

## Out of Scope

- Transposing or generating the actual preset JSON (Module 2.1 / 2.2)
- Validating the generated output (Module 2.3)

## Inputs

- Light ID
- Master preset ID
- Target preset ID (integer, must be unique on this light)
- `quick_label`: two-digit zero-padded sequence number unique within the light (e.g. `"01"`, `"14"`, `"22"`). Used as the prefix in the generated WLED preset name.
- `colour_mode`: one of `source` | `segment` | `custom` (default `source`)
  - `source` — copy colours exactly from the master preset
  - `segment` — substitute `col[0]` per segment with the characteristic colour from the light's segment config entry
  - `custom` — use explicit per-assignment colour overrides stored in `colour_slots`
- `palette_override` (optional integer): override the palette ID on all segments when generating
- `colour_slots` (optional JSON): when `colour_mode=custom`, a list of per-segment `[R,G,B]` colour overrides
- Sort order
- Notes

## Outputs

- Persisted records in `light_preset_assignments`
- Change log entries for all changes

## Generated Preset Naming

The generation engine builds the WLED `n` field from the assignment as follows:

| Preset type | Name template | Example |
|---|---|---|
| Standard / all-LED / segmented | `"{quick_label} {master_preset.name}"` | `"01 Rainbow"` |
| Build preset | `"{light.shortcode} Build {N} ({description})"` | `"RB Build 3 (mid)"` |
| Button / playlist | `n` passed through from master preset unchanged | |

The `quick_label` comes from the assignment record, not from the imported source file. Bulk-importing from a presets.json that already has numbered names (e.g. `"01 Rainbow"`) should strip the prefix and store only the effect name in `master_preset.name`.

## Slot Scheme Validation

Each light has an optional `preset_slot_scheme` (JSON). When defined, the assignment manager:
- Suggests the next available ID within the appropriate range when adding a new assignment
- Warns (but does not block) when a target preset ID falls outside the expected range
- Warns when a playlist button's `win` command references preset ID ranges that do not align with the scheme's live preset range

Example scheme for RB Proto:
```json
{
  "live_presets": [110, 131],
  "build_presets": [70, 77],
  "playlist_button": 50,
  "buttons": [1, 4],
  "utility_buttons": [100, 102]
}
```

## UI Screens

- **Assignment manager** — shown in context of a specific light; lists all current assignments with target ID, quick-label, and source preset name; drag-to-reorder; inline edit for target ID and label
- **Add assignment panel** — search/select from the master preset library; set target ID and label; warns if target ID is already in use on this light

## Key Rules and Constraints

- Target preset IDs must be unique within a light's assignment list
- `quick_label` must be unique within a light's assignment list and should be two-digit zero-padded (e.g. `"01"` not `"1"`)
- Sort order is used by the generation engine to determine the order of presets in the output file
- An assignment cannot reference a master preset that has been deleted
- `colour_mode` defaults to `source`; `palette_override` and `colour_slots` are nullable
- Slot scheme validation is advisory (warnings only); assignments outside the scheme are permitted

## Acceptance Criteria

- [ ] Can assign a master preset to a light with a target preset ID, quick-label, colour_mode, and optional palette_override
- [ ] Duplicate target preset ID within the same light is rejected with a clear error
- [ ] Duplicate quick-label within the same light is rejected
- [ ] `colour_mode` dropdown shows all three options and defaults to `source`
- [ ] When target ID falls outside the light's slot scheme range, a warning is shown (assignment is still saved)
- [ ] Reordering assignments persists and is reflected in the sort order
- [ ] Removing an assignment does not affect the master preset record
- [ ] Change log records all assignment changes

## Open Questions

- *Resolved*: Button presets follow the same assignment flow. The `win` command is preserved as-is by the transposition engine. The quick-label and naming convention do not apply to button presets (name is passed through).
