## Purpose

Define, create, and version all SQLite database tables. Provide example seed data for the RB prototype and Small Rainbow lights so development can proceed without manual data entry.

## Responsibilities

- Create all tables described in Section 8 of the project brief
- Apply schema via a migration tool so changes are versioned and repeatable
- Seed the database with example light profiles, segments, and imported files from the sample data in `sample_data/`
- Provide a reset/reseed command for development use

## Out of Scope

- Application logic that reads from or writes to these tables (handled per module)
- Any table not listed in the schema below

## Key Rules and Constraints

- Migrations must be versioned and run automatically on startup if the database is new or behind
- The database file path must be configurable via environment variable
- Foreign key enforcement must be enabled (`PRAGMA foreign_keys = ON`)
- `imported_files.raw_json` and `generated_files.raw_json` are never deleted or overwritten — they are immutable once written

## Seed Data

The seed script will create:
- Two lights: `Lightomation-RB-Proto` (388 LEDs, IP `192.168.0.186`) and `LoM Small Rainbow` (182 LEDs, IP `192.168.0.194`)
- Segment definitions for each light
- Default preset categories
- Imported file records from the JSON files in `sample_data/`

## Acceptance Criteria

- [ ] All tables created on first startup with no errors
- [ ] Migrations run cleanly on a fresh database
- [ ] Seed script populates RB Proto and Small Rainbow light profiles with correct segments
- [ ] `PRAGMA foreign_keys = ON` confirmed active
- [ ] Raw JSON in `imported_files` and `generated_files` cannot be overwritten by normal API operations
- [ ] Reseed command restores database to known state for development
