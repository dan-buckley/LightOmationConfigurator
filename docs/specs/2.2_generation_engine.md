# 2.2 Generation Engine

| Field | Detail |
|---|---|
| ID | 2.2 |
| Layer | Processing |
| Status | Backlog |
| Depends On | 1.4, 2.1 |
| Milestone | M2 |

## Purpose

Build a complete, valid WLED `presets.json` file for a target light by running all of its assigned master presets through the transposition engine and assembling the result into the correct WLED file format.

## Responsibilities

- Read all assignments for a target light in sort order
- Build a playlist ID map from the full assignment list before processing any preset (so playlist references can be resolved)
- Pass each assigned preset through the transposition engine (Module 2.1) with the correct source and target profiles, colour mode, palette override, and group hint
- Apply the naming template to set the WLED `n` field on each output preset
- Validate that all target preset IDs fall within the light's `preset_slot_scheme` ranges (include warnings in the report)
- Assemble the transposed presets into a valid WLED `presets.json` structure
- Store the generated file as a new record in `generated_files`
- Return a generation report including any transposition warnings and slot scheme violations

## Out of Scope

- Validating the generated file (Module 2.3)
- Exporting or deploying the file (Modules 3.1, 3.2)

## Inputs

| Input | Description |
|---|---|
| `light_id` | The target light to generate for |
| `notes` (optional) | User notes to attach to the generated file record |

## Outputs

| Output | Description |
|---|---|
| `generated_file_id` | ID of the new record in `generated_files` |
| `generation_report` | List of presets processed, any transposition warnings, and overall status |

## WLED `presets.json` Format

The output is a JSON object where each key is a string preset ID and each value is the preset object. The special key `"0"` holds an empty object `{}` as required by WLED.

```json
{
  "0": {},
  "1": { ...preset object... },
  "14": { ...preset object... }
}
```

## Processing Steps

1. Load the target light's profile, segments, active segment config (with entries and groups), `shortcode`, and `preset_slot_scheme` from the database
2. Load all assignments for the light, ordered by `sort_order`
3. Validate slot scheme: check each assignment's `target_preset_id` against the scheme ranges; collect any out-of-range warnings
4. Build `playlist_id_map`: `{ master_preset.source_preset_id: assignment.target_preset_id }` for all assignments
5. For each assignment:
   a. Load the master preset's `preset_data`, `category`, and `segment_group_hint`
   b. Determine the source light profile (from `master_preset.source_light_id`)
   c. Call transposition engine with:
      - source profile, target profile, target preset ID, playlist ID map
      - `colour_mode`, `palette_override`, `colour_slots` from the assignment
      - `segment_group_hint` from the master preset
   d. Apply the naming template to set `n` on the transposed preset (see below)
   e. Collect any transposition warnings
6. Assemble output JSON with `"0": {}` plus all transposed presets keyed by target preset ID (as strings)
7. Store the assembled JSON in `generated_files`
8. Return the generated file ID and report

## Naming Template

The `n` field on each output preset is set as follows:

| Preset category | Template | Example |
|---|---|---|
| Standard / all-LED / segmented | `"{assignment.quick_label} {master_preset.name}"` | `"01 Rainbow"` |
| Build preset | `"{light.shortcode} Build {N} ({description})"` | `"RB Build 3 (mid)"` |
| Button preset | `n` passed through from `master_preset.preset_data` unchanged | |
| Playlist preset | `n` passed through from `master_preset.preset_data` unchanged | |

Build preset `{N}` and `{description}` are stored in the master preset's metadata fields (added when the preset is categorised as a build preset).

## Key Rules and Constraints

- Generation always creates a new record in `generated_files`; it never overwrites an existing record
- If any assignment's transposition raises an error (not just a warning), generation halts and no file is stored
- The playlist ID map must be built from the full assignment list before any transposition begins, not preset by preset
- A master preset with no `source_light_id` is treated as layout-independent (button or all-LED with no segment mapping)

## Acceptance Criteria

- [ ] Generating for Small Rainbow produces a valid JSON file with all assigned presets at their target IDs
- [ ] The `"0": {}` entry is always present in the output
- [ ] Playlist ID references are correctly remapped using the assignment list
- [ ] Transposition warnings are included in the generation report
- [ ] Slot scheme violations (IDs outside expected ranges) are included in the generation report as warnings
- [ ] Preset `n` field follows the naming template: `"{quick_label} {name}"` for standard presets
- [ ] Button and playlist preset names are passed through unchanged
- [ ] A transposition error stops generation and no partial file is stored
- [ ] Each generation creates a new `generated_files` record; previous records are unchanged
- [ ] Generation report is returned to the caller and displayed in the UI
