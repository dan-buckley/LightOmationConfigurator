## Purpose

Establish the FastAPI application structure, routing skeleton, shared conventions, and base Pydantic models so that all subsequent modules have a consistent, predictable API layer to build on.

## Responsibilities

- Initialise the FastAPI application with CORS, exception handling, and lifespan events
- Define the router structure — one router per module group, registered at predictable path prefixes
- Define base Pydantic response models and error schemas used across all modules
- Provide a `GET /health` endpoint returning service and database status
- Establish database session management (connection per request, closed on response)
- Define a consistent API response envelope if used (e.g. `{ data, error, meta }`)
- Provide centralised error handling for validation errors, not-found errors, and unhandled exceptions

## Out of Scope

- Implementation of any endpoint beyond `/health` (handled per module)
- Frontend code

## Base Pydantic Models

- `SuccessResponse` — wraps any successful response payload
- `ErrorResponse` — standard error shape: `{ code, message, detail }`
- `PaginatedResponse` — wraps list responses with `{ items, total, page, page_size }`

## Key Rules and Constraints

- All endpoints must return consistent JSON shapes using the base models above
- CORS must be configurable via environment variable (origins list)
- Unhandled exceptions must return `500` with the `ErrorResponse` shape, not a raw traceback
- Request validation errors (Pydantic) must return `422` with field-level detail
- Database session must always be closed after the request, even on error
- API version prefix (`/api/v1`) should be applied to all routes for future compatibility

## Acceptance Criteria

- [ ] `GET /api/v1/health` returns `200` with database connection status
- [ ] All routers registered and return `404` on undefined sub-routes (not `500`)
- [ ] CORS headers present on responses when origin is in the allowed list
- [ ] Unhandled exception returns `500` with `ErrorResponse` shape
- [ ] Pydantic validation failure returns `422` with field-level errors
- [ ] Database session is cleanly closed after every request
