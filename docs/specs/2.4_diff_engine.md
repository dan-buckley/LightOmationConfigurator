# 2.4 Diff Engine

| Field | Detail |
|---|---|
| ID | 2.4 |
| Layer | Processing |
| Status | Backlog |
| Depends On | 1.2, 2.2 |
| Milestone | M2 |

## Purpose

Compare any two stored WLED `presets.json` files and produce a structured, human-readable diff that shows exactly what has been added, removed, or changed at the preset level. Supports reviewing changes before export or deployment, and understanding what changed between generations.

## Responsibilities

- Accept two file references (from `imported_files` or `generated_files`) and compare their content
- Identify presets present in one file but not the other (added / removed)
- Identify presets present in both files where one or more fields differ (changed)
- For changed presets, surface the specific fields that differ
- Return a structured diff report
- Display the diff in a readable UI view

## Out of Scope

- Generating files (Module 2.2)
- Validating files (Module 2.3)
- Line-level text diff of the raw JSON (not useful; structure-level diff is more actionable)

## Inputs

| Input | Description |
|---|---|
| `file_a_type` | `imported` or `generated` |
| `file_a_id` | ID in the relevant table |
| `file_b_type` | `imported` or `generated` |
| `file_b_id` | ID in the relevant table |

## Outputs

| Output | Description |
|---|---|
| `diff_report` | Structured object with `added`, `removed`, and `changed` preset lists |

## Diff Report Structure

```json
{
  "file_a": { "id": 12, "type": "imported", "label": "Imported 2026-05-10" },
  "file_b": { "id": 7, "type": "generated", "label": "Generated 2026-05-16" },
  "summary": { "added": 2, "removed": 1, "changed": 4, "unchanged": 11 },
  "added": [ { "preset_id": "15", "name": "New Effect" } ],
  "removed": [ { "preset_id": "8", "name": "Old Effect" } ],
  "changed": [
    {
      "preset_id": "3",
      "name": "Rainbow Solid",
      "fields_changed": [ "sx", "seg[0].stop", "seg[1].start" ]
    }
  ]
}
```

## Key Rules and Constraints

- Preset identity for comparison is based on the preset ID key in the JSON object
- The engine must ignore the `"0"` key (always empty)
- Field-level change detection must go one level into segment arrays (detect `seg[i].start`, `seg[i].stop`, `seg[i].fx`, etc.)
- Ordering differences alone (e.g. same presets in a different key order) must not be reported as changes
- The diff engine is read-only and has no side effects

## API Endpoints

| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/diff` | Compare two files; body contains both file references |

## UI Screens

- **Diff viewer** — shown after generation or accessible from history; split layout showing summary counts and then the three groups (added, removed, changed); changed presets expand to show the specific fields that differ

## Acceptance Criteria

- [ ] Comparing a file with itself returns zero changes in all categories
- [ ] Adding a preset to a generated file compared to the source import shows it in `added`
- [ ] Removing a preset shows it in `removed`
- [ ] Changing a segment boundary on a preset shows it in `changed` with the specific field identified
- [ ] Reordering keys in the JSON without changing values shows no changes
- [ ] Diff is accessible between any combination of imported and generated files

## Open Questions

- Should diff results be stored or are they always computed on demand?
- Should the UI show the full preset JSON side-by-side for changed entries, or just the field list?
