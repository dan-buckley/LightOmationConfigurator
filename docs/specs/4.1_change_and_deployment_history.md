# 4.1 Change and Deployment History

| Field | Detail |
|---|---|
| ID | 4.1 |
| Layer | Visibility |
| Status | Backlog |
| Depends On | 3.1 |
| Milestone | M4 |

## Purpose

Provide a complete, chronological audit trail for every significant action in the system. Users can review what happened to any light, retrieve any stored file version, and understand the sequence of changes over time.

## Responsibilities

- Display a per-light timeline of all events: imports, generations, exports, and deployments
- Allow the user to view and download the raw JSON for any stored `imported_files` or `generated_files` record
- Display the change log for structural data (lights, segments, presets, assignments)
- Provide a system-wide activity feed showing recent actions across all lights

## Out of Scope

- Generating or modifying any data (history is read-only)
- Rollback (restoring a previous state) — Later Scope

## Data Sources

| Table | What it contributes |
|---|---|
| `imported_files` | Import events with timestamp, source, and raw JSON |
| `generated_files` | Generation events with timestamp and raw JSON |
| `exported_files` | Export events with timestamp and method |
| `deployment_history` | Push events with timestamp and result |
| `change_log` | Structural changes to lights, presets, and assignments |

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/api/v1/history/lights/{id}` | Chronological event timeline for a light |
| GET | `/api/v1/history/activity` | Recent activity across all lights |
| GET | `/api/v1/history/imports/{id}/raw` | Raw JSON for an imported file |
| GET | `/api/v1/history/generated/{id}/raw` | Raw JSON for a generated file |
| GET | `/api/v1/history/generated/{id}/download` | Download a historical generated file |

## UI Screens

- **Light history view** — tabbed or scrollable timeline per light; events grouped by type with expand-to-detail; links to view or download file content for file-based events
- **System activity feed** — reverse-chronological list of all recent events across all lights; filterable by event type
- **Raw file viewer** — inline JSON display (syntax highlighted) for any stored file

## Key Rules and Constraints

- History views are read-only; no modifications can be made from these screens
- All file content is retrieved from the database; no filesystem reads required
- A historical generated file downloaded from history must be clearly labelled with its generation date to distinguish it from the current version
- The change log view must show before and after state for updated records

## Acceptance Criteria

- [ ] Light history for Small Rainbow shows all imports, generations, exports, and deployments in order
- [ ] Clicking any import or generated file event opens the raw JSON viewer
- [ ] Downloading a historical generated file produces a correctly named and complete JSON file
- [ ] System activity feed shows events from all lights
- [ ] Change log entries for light profile updates show the before and after state

## Open Questions

- Should events be paginated on the light history view, or loaded on scroll?
- Should the change log be shown inline in the light history, or as a separate tab?
